本文是 `alliance/client` 界面美化的计划：以 master（`legacy/`）的视觉为参照，修好现有页面的布局，并把按钮、弹窗等沉淀为可复用、可导出给模组的 `ui/` 组件。规格以 APP.md、ARCH.md「前端」与文档 `docs/alliance/maintain/client/` 为准，本文只写计划；落地后的规格写进文档，评审并修改完之后，本文对应条目删除。

## 范围

- 页面：入口（标题）、大厅、房间、简报、选策略、对局 HUD、结算，以及个人配置、干员调配、确认框三类对话框。
- 组件：`ui/` 的通用组件与游戏专用小件，按令牌重做，经包入口导出给模组。
- 提示（大厅「作战提示」轮播）与帮助（玩法说明内容）本轮不做，只保留入口位置。
- 组件展示页本轮不做，以后以组件库形式（如 Storybook）提供；组件按「纯 props、不读仓库」编写，便于日后直接写成 story。

## 方案

### 结算预览

优先级低，排在最后（T12）。在调试 API 增加客户端命令，把录制的帧流（`m.public`、`m.private`、`m.result`）灌进状态仓库并导航到对应页面，不经连接；只在开发构建可用，写进 DEBUG.md 与 `18-debug.md`。结算、对局 HUD 的各种状态都可以这样预览，也为以后 Storybook 的数据夹具复用。

## 组件规格

全部放在 `ui/`，只读语义令牌，经 `ui/index.ts` 导出给模组。变体 API 参照 shadcn：`variant`、`size`、`tone`（`Button` 的色调由 `variant` 决定，`TextField` 的由状态决定，两者不另设 `tone`）；实现用组件根节点的 `data-variant` / `data-size` / `data-tone` 加 CSS Modules，不引入 cva 等运行时依赖。

| 组件 | 要点 | master 参照 | next 现状 |
|---|---|---|---|
| `PageBar` | 页面顶栏：左（退出/返回、延迟、工具）｜中（微标签 + 标题，可带步骤数）｜右；大厅、房间、简报、选策略共用 | `components.css` shared screen chrome | 大厅、简报各写一份 |
| `SevenSeg`、`Countdown`、`ProgressBar`、`Spinner`、`Tabs` | 换皮 | 同名 | 有 |

约束：

- 组件不读状态仓库、不发意图；音效反馈仍经 `useFeedback`。
- props 有类型，作为模组 API 的一部分；改名或删字段按 ARCH.md 的版本策略处理。
- 页面模块 CSS 只做排布，不再重画按钮、面板、角标框。

## 任务

依赖关系：T3 → T4 至 T11；T4 至 T11 彼此可并行；T12 独立，优先级最低。基础（画布、单位、令牌、字体，规格见 `docs/alliance/maintain/client/11-style.md`）、通用组件（`Button`、`Panel`、`Segmented`、`SelectCard` 等）与浮层组件（`Dialog`、确认框、`Popover`、`Tooltip`、`ToastStack`、连接横幅）已完成，规格见 `docs/alliance/maintain/client/19-component.md`。

验收：1280×720、844×390、1024×768（4:3）、2560×1080（21:9）下与 master 并排截图交用户审阅，后两者重点看边带装饰；键盘可达。中间任务可只做到截图验收，最后一个任务统一跑 `pnpm --filter @alliance/client check`、`test`、`lint`。

### T3 页面骨架

`PageBar`；`core:match.stephead` 改用它；大厅顶栏改用它。

### T4 入口页

`core:entry.hero`（塔形标志用 SVG 自绘、英文双行标题、中文大标题与强调色、标语）、`core:entry.name` 表单卡、角落区重排（语言改下拉、设置与全屏为方键、连接状态点）、页脚（免责声明与版本）。参照 master `screens/title.js`、`css/screens/title.css`。

### T5 大厅

模式卡与难度卡改用 `SelectCard`；创建按钮 `xl`；加入面板用 `wsde-brackets` 角标框。「作战提示」不做。参照 `screens/lobby.js`、`lobby.css`。

### T6 房间

`core:room.header` 用 `PageBar`（右侧同盟密钥用 `SevenSeg` + 复制键）；席位卡（`AvatarFrame`、创建者标、空席雷达与「添加 AI 队友」）；底栏（`Segmented` 难度、AI 最后选择、就绪人数、干员调配与开始）；独立模拟的席位 + 说明并排。参照 `screens/room.js`、`room.css`。

### T7 简报

步骤头；左栏领袖卡（`Panel tone="orange"`）、战场行、特训敌人列表；右栏盟约圆片区（`SectionHeading`）、禁用干员网格；重刷本局面板；底部操作。参照 `screens/briefing.js`、`briefing.css`。

### T8 选策略

决策顺序卡、策略网格（`SelectCard` + 立绘 + LP 塔）、详情卡、跳过/确认。参照 `screens/bandDraft.js`、`draft.css`。

### T9 对局 HUD

顶部胶囊组居中并加角标框、「准备就绪」右上；队伍栏、盟约条、效果列换皮；商店卡加立绘、等级卡与资金 `HexBadge`；商店栏高度按画布比例重定（APP.md「界面待办」视觉布局两条随之关闭）；角落键与表情轮盘；阶段横幅按阶段配色；HUD 占位量改 dp 并同步相机内边距：上边距要把顶栏下方的盟约条区域也算进去（1024×768 下盟约条压到了棋盘顶行，原因是目前只算了顶栏）。战场本身不在此任务。参照 `screens/game.js`、`game*.css`、`ui/shopBar.js`、`ui/hud.js`。

### T10 结算

按 master 布局换皮：背景与网格、胜负标题、通过回合、领袖徽章、用时、玩家卡（策略、阵容头像、数据 4×2、评语）。预览依赖 T12，T12 未完成前可打一局 FUNNY 难度验收。参照 `screens/result.js`、`result.css`。

### T11 对话框内容

个人配置（行式表单：标签 + 微标签 + 控件，底部操作）、干员调配（`full` 框体）换皮。玩法说明只换外框。参照 `ui/settings.js`、`loadout.css`。

### T12 调试预览（低优先级）

按「结算预览」一节设计并实现调试命令与帧流夹具格式，提供结算、对局 HUD 若干状态的夹具。

## 对照方法

1. master：`legacy/` 下 `npm start`（端口 3000）。
2. next：`alliance/client` 下 `pnpm dev`，经 Vite 代理连 3000。
3. 无头 Chrome 加 `--use-angle=swiftshader --enable-unsafe-swiftshader` 才有 WebGL；资源加载需等待 6–10 秒再截图。
4. next 可经 `window.wsde`（`enter`、`createRoom`、`submit`）推进流程；master 按按钮文本点击。

已知问题：长时间运行的 next 开发服务器 `/ws` 代理会卡住（页面停在「正在连接服务器」，`/data` 等 HTTP 代理正常），重启开发服务器即恢复。原因未查。
