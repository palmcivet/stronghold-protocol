# 干员调配同步

干员调配有三项配置。客户端在本地保存工作副本，并发给服务端。服务端把它们存在会话与席位上，开局时采用。

| 配置 | 消息 | 内容 |
| --- | --- | --- |
| 调配 | `room.loadout` | `entries`：每名干员的技能与模组；`ops`：潜能与练度，按 charId |
| 持有与替补 | `room.ownership` | `notOwned`：设为未持有的干员 |
| 自选编队 | `room.diy` | `picks`：每个自选格的干员、`skillIndex` 与 `uniEquipId` |

- 工作副本按服务端划分保存，见 [本地存储](./08-storage.md#宿主的存储项)。
- 调配发送前按已载入的数据剔除服务端会拒收的项。数据未载入时，非空的调配等数据载入后再发。
- 空调配发 `{ entries: {}, ops: {} }`。

## 发送时机

- 每次收到 `welcome` 后三项都重发：先持有与自选，再调配。
- `room.state` 的 `inMatch` 变为 `false` 时，重发上一局中被锁定的项。
- 玩家修改后自动保存：停止修改 500 毫秒后发送对应的项。
- 关闭对话框时，尚未发出的修改立即发送，不会被玩家的下一次操作（如简报中的准备）抢先。

## 同步状态

| 状态 | 含义 |
| --- | --- |
| `idle` | 尚未发送 |
| `pending` | 已修改，等待发送 |
| `sending` | 发送中 |
| `synced` | 服务端已接受 |
| `locked` | 服务端已保存，但本局不再采用 |
| `error` | 发送失败 |

回复 `WRONG_PHASE` 或 `ROOM_STARTED` 时状态为 `locked`。两种回复都表示服务端已经保存，下一局生效。界面显示「已保存，下一局生效」。

## 生效时机

| 当前阶段 | 调配 | 持有与自选 |
| --- | --- | --- |
| 不在对局中 | 下一局 | 下一局 |
| 简报 `INFO_CHECK` | 本局 | 下一局 |
| 简报之后 | 下一局 | 下一局 |

对话框的每一页按当前阶段标出修改的生效时机。
