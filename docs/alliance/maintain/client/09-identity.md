# 身份与多标签

服务端用重连令牌认出玩家。每个标签在页面载入时选定一个令牌，在第一次 `hello` 之前确定。同一设备上的多个标签经 BroadcastChannel 协商，保证两个活着的标签不使用同一个令牌。

## 选择顺序

页面载入时：

1. 本标签自己的令牌（`secureTab`），刷新本标签后仍在，新标签不继承。
2. 没有时，在有 BroadcastChannel 的浏览器里，取本设备最近令牌列表中没有被其他活着的标签占用的那个。关闭标签后在服务端的重连时限内重开，可以回到原来的席位。
3. 都没有时不带令牌连接，由服务端分配新令牌。

没有 BroadcastChannel 时只用本标签自己的令牌。

## 标签间协商

- 频道名是 `wsde:identity`。
- 标签之间只广播令牌哈希（FNV-1a），不广播令牌本身。
- 询问「谁持有这些令牌」后等待约 150 毫秒的回答。

多个标签争同一个令牌时，按以下顺序决定胜者：

1. 先收到 `welcome` 的
2. 其次是活着的持有者
3. 最后比较标签 id

复制出来的标签因此成为新玩家，不会把原标签挤下线。

## hello 字段

| 令牌来源 | `hello` 附带 |
| --- | --- |
| 本标签自己的令牌 | `claimAt`：该令牌首次 `welcome` 的时间 |
| 最近令牌列表中的候选 | `noReplace`：不顶替已连接的会话 |

服务端回复 `SESSION_IN_USE` 时，本页放弃这个令牌，用下一个选择重连。

## 跟随连接

- 收到 `welcome` 时保存其中的令牌，并更新最近令牌列表。
- 收到 `room.state` 且玩家在进行中的对局里入座时，记下这个令牌所在的对局（代号与房间码）。

## 恢复本机对局

已关闭标签的席位不会自动恢复。入口页的「恢复本机对局」（`core:entry.resume`）列出最近令牌中记有对局的项，由玩家显式选择：

1. 再问一次活着的标签，确认没有标签占用这个令牌
2. 本页改用这个令牌
3. 重新连接

存储项见 [本地存储](./08-storage.md#宿主的存储项)。
