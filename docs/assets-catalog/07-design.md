# 设计

## 键是身份，哈希只用于校验

资源的身份是键，不是内容哈希。同一份字节出现在两个键下（例如头像与皮肤立绘恰好相同）就是两个资源，各有条目、各有地址、各占一条缓存。内容哈希只用于下载校验、清单 `contentHash`、浏览器缓存的 `?v=` 与增量发布。

跨包只传键：种类从键推出，地址由地址模块算出，回退目标 `fallbackId` 写在清单条目上。

## 清单只放引用

包清单没有上游地址、没有 Spine 动画信息、没有游戏领域字段。领域 id 到键的映射写在 `refs`，形状由打包方定义，本包只要求叶子是合法键。这样同一个解析器可以服务任何使用这套资源的项目。

## 覆盖层

解析器把清单从低到高叠起来：

- 同一键，高层整条替换低层。部分字段合并会让一个条目的文件来自两个包，校验与回退都不再可靠。
- `refs` 按 JSON 路径合并，模组可以只改一个干员的一个槽位。
- 回退沿 `fallbackId` 进行，每一环都取最高层的条目，所以模组既能替换资源本身，也能替换它的回退目标。

物理回退（`fallbackId`）与领域回退不同：精英二头像缺失时用精英零头像，由打包方把两个键都写进清单并设置 `fallbackId`；解析器只执行这条链，不推断领域规则。

## 一套地址

开发、部署与提取缓存使用同一套相对地址，所有种类同一格式，没有按种类的特殊路由。文件用可读路径加 `?v=<hash>`，开发时容易排查，跨包去重靠共享的 `/res/files/` 目录。
